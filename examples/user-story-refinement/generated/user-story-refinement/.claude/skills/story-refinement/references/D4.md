**Task: "Beispieltabellen ergänzen (Specification by Example)"** (QA). Turns the rules and
Given-When-Then scenarios from D3 into rows of concrete inputs and expected outputs.

**Source limit:** the notebook states that it holds no Specification-by-Example book or dedicated SbE
method. It answers from Cohn's tabular acceptance tests (FIT/FitNesse), decision tables in the German
requirements-engineering texts and Patton's example lists [^1]. What follows is therefore "example
tables" as those sources describe them.

### Procedure

1. **Columns:** one column per input (card type, expiration, number) and a last column with the
   expected result (valid: true/false). Each row is one set of data [^2][^3].
2. **Rows:** start with a simple, obvious, concrete example, then a complex one; you are creating a
   range of constraints, not promising everything [^4]. Cover valid and invalid values, expired
   cards, over-the-limit amounts, missing or bad numbers, as in the credit-card test list [^5].
3. **How many:** no fixed number. Add rows while they clarify the intent; stop when they don't.
   Leave low-level cases (invalid dates such as February 30) to the developers' unit tests [^6][^7].
4. **Complex rules:** put multi-condition if-then rules into a decision table; it shows gaps,
   overlaps and contradictions, and the missing "what if the condition is not met" cases [^8][^9].
5. **Afterwards:** the table is the executable acceptance test (FIT/FitNesse): each row is run, result
   cells turn green or red; it also serves as the done criterion and as shared documentation for
   business and development [^10][^11][^12].

### Pitfalls

- Too many rows, low-level duplicates of unit tests [^6].
- Incomplete conditions: a rule that only states what happens when the condition holds [^9].
- UI or technical detail in the examples, or solution-shaped framing ("Cash report" instead of
  the question "How much potential cash is in blocked projects?") [^13].

### Terminology

- **FIT / FitNesse**: tools that run tables of data values and expected results as tests [^11].
- **Entscheidungstabelle (decision table)**: table of condition combinations and resulting actions [^8].
