## Product-Methodik: Plausibilität & Freigabe

_Ort: notebook:The Product - Business Design_

_Footnotes name the notebook source. The verbatim quotes and FAQ references stay with the generation output (`knowledge/`), which is not installed._

**Task:** "Auf Duplikate & Überschneidungen prüfen" (PO). Input: the new ready story plus the whole product backlog.

**Procedure (in order)**

1. Compare goal and user need (role, "I want", "so that") with existing items. Two stories can be worded or solved
   differently and still serve the same need [^1].
2. Compare terms with glossary and domain model: the same concept may sit under another name (synonym), or the
   same word may mean two things (false cognate, e.g. "Charge") [^2][^3].
3. Compare scope and acceptance criteria: shared functional area or shared test cases signal overlap [^4].
4. Classify and decide:
   - **Full duplicate** (same concept or intent): discard or archive the new story, or link it to the existing
     item; never keep the concept described twice [^2][^5].
   - **Partial overlap** (different output, shared work): combine for planning, split again only when slotted
     into an iteration [^4]. Hand over to "Mit bestehender Story zusammenführen".

**Output:** duplicate/overlap findings with the compared stories named; cross-references (Querbezüge) between
interdependent stories [^6].

**Checklist**

- Concrete role? Generic roles ("As a user ...") hide duplicates and pet features [^7].
- Is the story a solution rather than a need? Compare the goal behind it [^1].
- Checked the documented "Won't" items, so already rejected requests are not analysed again [^5].
- Compared against current functional specification and tests, not by reading old stories in reverse
  chronological order [^8].
- Reviewer is not the story's author: authors miss their own duplicates [^9].

**Pitfalls**

- Same wording taken as the same concept (false cognate) [^3].
- Small overlapping stories left uncombined; estimates then depend on build order [^4].

**Not answered by the notebook:** no similarity threshold or tooling is given for deciding "duplicate" versus
"overlap" beyond the definitions above.
