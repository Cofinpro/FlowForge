# Domain knowledge — MVP & Release-Roadmap abgrenzen

- MVP: a balanced vertical slice (feasible, valuable, usable, delightful), not one technical layer; it must yield learning toward a goal [^1].
- "Minimum Viable Product: build a slice across instead of one layer at a time" [^1].
- Walking skeleton = first slice through all backbone activities; opening game → midgame → endgame orders the rest [^2].
- Pass: 2D grid (horizontal is narrative, vertical is priority); no orphaned cards [^3][^4].
- Pitfall: horizontal cake slicing; the "all must-have" priority-one paradox under MoSCoW [^4][^1].
- Dark-factory rule: the MVP fits the budget and timebox from the idea brief (rubric `mvp`); `budget`/`timebox` is a mandatory brief field, assumed and marked 🧠 if missing (Gedächtnis §14).
- G-P3 passes only with critic `pass` (rubric `gate-mvp`), ≥ 3 of 4 target users "would use" ≥ 4/5 and ≥ 2 of 4 with willingness to pay matching the lean-canvas pricing (Gedächtnis §9.2).

[^1]: "Lean Enterprise" (Humble, Molesky, O'Reilly) — "Minimum Viable Product: build a slice across instead of one layer at a time … valuable, usable, and feasible … to which we add 'delightful'."
[^2]: "User Story Mapping" (Patton) — "I call this first slice a functional walking skeleton … Opening game: Focus on the essential features or user steps that cross through the entire product … Midgame … Endgame."
[^3]: "Mapping Experiences" (Kalbach 2020) — "Frame the idea … Write your responses down at the top of the map. Map the big picture … Explore … Create a release strategy."
[^4]: "Fifty Quick Ideas to Improve Your User Stories" (Adzic et al. 2014) — "A story map is a grid where the horizontal axis represents steps in a high-level user activity, and the vertical axis represents the software delivery schedule." / "put it on crutches and ship it out."
