# Domain knowledge — Outcome-basierte Release-Ziele festlegen

- The mapping sequence ends with "Create a release strategy" after framing, big picture and exploration [^1].
- MVP: a balanced vertical slice (feasible, valuable, usable, delightful), not one technical layer; it must yield learning toward a goal [^2].
- Rubric `roadmap`: outcome instead of feature phrasing; reference to GOAL/IMP (Gedächtnis §13).
- Rubric `mvp`: every slice has a learning goal and a reference to GOAL (Gedächtnis §13).
- The One Metric That Matters sits on an AARRR stage (adopted source addition in 1.2.1); release metrics should use it or a leading indicator.

[^1]: "Mapping Experiences" (Kalbach 2020) — "Frame the idea … Write your responses down at the top of the map. Map the big picture … Explore … Create a release strategy."
[^2]: "Lean Enterprise" (Humble, Molesky, O'Reilly) — "Minimum Viable Product: build a slice across instead of one layer at a time … valuable, usable, and feasible … to which we add 'delightful'."
