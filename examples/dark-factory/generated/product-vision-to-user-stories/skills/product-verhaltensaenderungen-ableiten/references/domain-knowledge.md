# Domain knowledge — Verhaltensaenderungen ableiten (How)

## Impacts (1.2.3)

- Four levels in order: Goal → Actors → Impacts (how: behaviour changes) → Deliverables [^1].
- Pass: impacts are actor behaviour changes, not features [^1].
- Pitfall: a feature as goal or impact ("build a mobile app") [^1].

## Rubric seed (Gedächtnis §13, `impact-map`)

- Strict hierarchy Goal → Actor → Impact → Deliverable; impacts as measurable behaviour change; deliverables as options (Adzic).

[^1]: "Fifty Quick Ideas to Improve Your User Stories" (Adzic, Evans, Korac 2014) — "capture user stories, epics, tasks, product ideas – all the deliverables that could potentially cause a positive impact … Then treat them as options, not as commitments."
